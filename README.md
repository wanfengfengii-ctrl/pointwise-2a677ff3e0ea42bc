# cycle_count — 三表循环关联总行数的增量维护

数仓加工场景：R(a,b)、S(b,c)、T(c,a) 三条关系各自带非负整数重数，
需要随三表的增删（重数 ±delta）始终维护循环关联总行数

```
TOTAL = Σ_{a,b,c} mR(a,b)·mS(b,c)·mT(c,a)
      = Σ_{(a,b)∈R} Σ_{(b,c)∈S} Σ_{(c,a)∈T} mR(a,b)·mS(b,c)·mT(c,a)
```

而不必反复执行完整关联。纯 Python 标准库实现，无第三方依赖。

## 接口

```python
from cycle_count import CycleCount

cc = CycleCount(r, s, t)          # r/s/t：各自无重复的字符串键对列表，
                                  # 分别限定 R(a,b)、S(b,c)、T(c,a) 的允许键对；
                                  # 三类键空间独立，初始重数全为 0
cc.add(table, left, right, delta) # table 仅 'R'/'S'/'T'；delta 为非布尔整数；
                                  # 返回调整后的当前总数
cc.count()                        # 返回当前总数
cc.probe(); cc.reset_probe()      # 诊断：字典/集合操作与整数乘加计数
```

非法 table、非整数/布尔 delta、未知键对、或会导致负重数的更新均抛
`ValueError` 且**状态不变**（所有校验在任何修改之前完成）。

规格示例：

```python
cc = CycleCount([['a','b']], [['b','c']], [['c','a']])
cc.add('R','a','b', 2)   # -> 0
cc.add('S','b','c', 3)   # -> 0
cc.add('T','c','a', 4)   # -> 24
cc.add('S','b','c',-1)   # -> 16
```

## 索引结构与不变量

记 M = |R|+|S|+|T|（允许键对总数），阈值 θ = √(M+1)。对每条关系的每一侧，
按**静态度数**（该侧值出现的允许键对数，与重数无关，构造时一次算定）分类：

- `deg(v)² > M+1` ⟺ v 为**热点**（邻居数 > θ）；否则为**冷点**（邻居数 ≤ θ）。
- 每侧度数之和 ≤ M，故每侧热点数 < M/θ < θ。

维护三张"热点×热点"部分和表（缺失键视为 0）：

```
ST[a,b] = Σ_c mS(b,c)·mT(c,a)   仅当 b 为 S-热点 且 a 为 T-热点
RT[b,c] = Σ_a mR(a,b)·mT(c,a)   仅当 b 为 R-热点 且 c 为 T-热点
RS[a,c] = Σ_b mR(a,b)·mS(b,c)   仅当 a 为 R-热点 且 c 为 S-热点
```

**不变量**：每次 `add` 返回后，以上三式对所有热点-热点键对精确成立。
构造时重数全 0、表为空，不变量平凡成立；更新时按如下传播规则增量维护
（被更新关系本身的重数不进表，故每条规则只读另两条关系的重数）：

```
R(a,b) += δ :  RT[b,·] += δ·mT(·,a)（对所有 T-热点 c，要求 b 为 R-热点）
               RS[a,·] += δ·mS(b,·)（对所有 S-热点 c，要求 a 为 R-热点）
S(b,c) += δ :  ST[·,b] += δ·mT(c,·)（对所有 T-热点 a，要求 b 为 S-热点）
               RS[·,c] += δ·mR(·,b)（对所有 R-热点 a，要求 c 为 S-热点）
T(c,a) += δ :  ST[a,·] += δ·mS(·,c)（对所有 S-热点 b，要求 a 为 T-热点）
               RT[·,c] += δ·mR(a,·)（对所有 R-热点 b，要求 c 为 T-热点）
```

## 更新算法（以 R(a,b) += δ 为例，S/T 对称）

1. **求增量** Q = Σ_c mS(b,c)·mT(c,a)：
   - b 为 S-热点且 a 为 T-热点 → O(1) 查 `ST[a,b]`；
   - 否则至少一侧为冷点，扫描**度数较小一侧**的邻居列表（≤ θ 项）逐项查表求和。
   - 无论哪种情况都**不扫描热点（度数 > θ）的全部邻居**。
2. `TOTAL += δ·Q`；更新 `mR(a,b)`（归零即删除，可重加）。
3. **传播**：按上表维护 RT、RS——各遍历一个长度 < θ 的热点列表。

## 复杂度（按整数算术与字典/集合操作次数计）

| 项目 | 界 | 说明 |
|---|---|---|
| 空间 | O(M+1) | 允许键对集合、双向邻居索引、重数字典合计 O(M)；三张部分和表各 < θ² = M+1 项 |
| 预处理 | O(M)（≤ O(M·√(M+1))） | 建索引、度数与热点分类；部分和表初始为空，无需联接预计算 |
| 单次更新 | 期望 O(√(M+1)) | 步骤 1 至多 θ 个邻居或 O(1) 查表；步骤 3 至多 2θ 次迭代；字典/集合操作期望 O(1) |

## 独立三重循环逐步核验

`verify_cycle_count.py` 中的参考模型与被测实现完全独立：只按规格直接维护
重数字典，总数一律用字面三重循环 `for (a,b)∈R: for (b',c)∈S: for (c',a')∈T`
从零重算。核验内容：

- 规格示例逐步返回值 `0, 0, 24, 16`；
- 归零重加、三表交错修改，每步与三重循环结果比对；
- 18 种非法更新（非法 table、布尔/浮点/字符串 delta、未知键对、负重数、
  不可哈希键等）均抛 `ValueError` 且状态不变；
- 边界：空关系、无三角形实例、delta=0、大整数（10³⁰ 级重数）；
- 随机交错操作序列（多种子 × 稠密/稀疏/星型/三种完全三部形状，
  分别触发 ST/RS/RT 三张热点表），**每一步**比对 add 返回值与 count()；
- 复杂度回归：星型热点场景单次更新访问量为小常数，稠密场景 ≤ 4θ+16。

运行：`python3 verify_cycle_count.py`（输出 `ALL CHECKS PASSED` 即通过）。

## 热点倍增实测（访问量 / 耗时 / 峰值内存）

`python3 bench_cycle_count.py` 实测，环境：Python 3.11.2，
Linux 6.12.69（aarch64）。"访问/次"指单次 add 的字典/集合操作次数
（实现内置诊断计数 `probe()`）；耗时为多次重复取最小后的单次平均。

### 场景 A：单热点星型，热点度 D 倍增（M = 2D+1）

一个 S-热点 b0 与一个 T-热点 a0（度均为 D），R 仅 (a0,b0)。朴素实现更新
R 时需扫描热点的全部 D 个邻居；本实现走热点×热点部分和表 ST。

| D | M | √(M+1) | 本实现 访问/次 | 朴素 访问/次 | 本实现 耗时/次 | 朴素 耗时/次 | 峰值内存 |
|--:|--:|--:|--:|--:|--:|--:|--:|
| 2048 | 4097 | 64.0 | 9.0 | 4,096 | 615 ns | 234.11 µs | 1.31 MiB |
| 4096 | 8193 | 90.5 | 9.0 | 8,192 | 669 ns | 512.10 µs | 2.36 MiB |
| 8192 | 16385 | 128.0 | 9.0 | 16,384 | 609 ns | 1.08 ms | 5.22 MiB |
| 16384 | 32769 | 181.0 | 9.0 | 32,768 | 619 ns | 2.29 ms | 9.43 MiB |
| 32768 | 65537 | 256.0 | 9.0 | 65,536 | 645 ns | 5.42 ms | 21.37 MiB |
| 65536 | 131073 | 362.0 | 9.0 | 131,072 | 635 ns | 13.94 ms | 38.83 MiB |

热点度倍增 32 倍，本实现单次更新访问量恒为 9 次、耗时约 0.6 µs 不变；
朴素实现访问量与耗时随 D 线性增长（约 2 万倍恶化）。峰值内存随 M 线性增长。
